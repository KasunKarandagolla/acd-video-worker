## Key Implementation Details

### 1. Dynamic Footage Requirements (replaces fixed 10-slot template)

The `FootageRequirementsGenerator` creates a Hermes-driven plan where each requirement contains:

```json
{
  "slot_id": "req_pressure_01",
  "purpose": "Establish pre-match tension via Messi tunnel walk",
  "story_section": "pressure_doubt",
  "required_emotion": "tension",
  "desired_subject": "Messi Argentina",
  "desired_action": "tunnel walk focused expression",
  "visual_type": "closeup",
  "priority": 1,
  "minimum_clips": 2,
  "search_terms": ["Messi tunnel walk World Cup 2022", "Argentina pre-match pressure"],
  "alternative_terms": ["Messi pre-match focus", "World Cup final tunnel"],
  "optional": false,
  "estimated_duration_seconds": 5.0,
  "story_role": "hook_reference",
  "platform_considerations": {"aspect_ratio": "16:9"}
}
```

**Generated by:** Hermes via `football-story-strategy` skill (or fallback template for dry-run)  
**Replaces:** Fixed 10 legacy slots (still available as emergency defaults)  
**Validation:** `plan.validate()` ensures ≥3 critical requirements, no duplicates, all have search terms

### 2. Fallback Discovery (Tavily + Hermes web search)

- **Primary:** yt-dlp `ytsearchN:query` (Kaggle-compatible, no browser)
- **Fallback:** Tavily API restricted to `site:youtube.com` (uses `TAVILY_API_KEY`)
- **Activation:** Only when primary returns < `min_candidates_per_slot` (default 3)
- **Deduplication:** Against primary results by `video_id`
- **Normalization:** Same `SourceCandidate` model as primary

### 3. Stage Orchestration (15 stages)

```
REQUEST
→ STORY_UNDERSTANDING          (social-edit-reasoning, football-story-strategy)
→ FOOTAGE_REQUIREMENTS         (football-story-strategy)
→ FOOTAGE_DISCOVERY            (football-source-discovery + fallback)
→ FOOTAGE_ACQUISITION          (football-footage-acquisition)
→ VISUAL_ANALYSIS              (football-visual-scene-analysis)
→ TIMESTAMP_EXTRACTION         (football-timestamp-extraction)
→ CLIP_SCORING                 (football-clip-scoring)
→ NARRATION                    (football-narration-scriptwriting)
→ AUDIO_PLAN                   (music-selector, audio-music-director, ducking-mixer)
→ EDIT_PLAN                    (pro-cutting-pacing, caption-thumbnail, edit-planning, audio-mapper)
→ OPENMONTAGE_IDEA             (idea-director)
→ OPENMONTAGE_SCENE_PLAN       (scene-director)
→ OPENMONTAGE_ASSETS           (asset-director)
→ OPENMONTAGE_EDIT             (edit-director, schema-locked)
→ OPENMONTAGE_COMPOSE          (compose-director, FFmpeg render)
→ QUALITY_REVIEW               (retention-QC, audio-QC, platform-validator)
→ DELIVERY                     (Discord notify, copy to outputs/)
→ MEMORY_UPDATE                (hermes-football-memory-learning)
```

**Each stage:**
- Invokes Hermes with skill-activating prompt
- Validates output artifacts against OpenMontage schemas
- Saves checkpoint (atomic write + history archive)
- On validation failure → targeted loopback (see below)

### 4. Checkpoint/Resume

- **Per-stage checkpoints:** `project_dir/checkpoints/<stage>.json` + `history/`
- **Project state:** `project_dir/checkpoints/project_state.json`
- **Resume:** Load state, find last completed stage, continue from next
- **Atomic writes:** `.tmp` → `os.replace()`; superseded archived to `history/`

### 5. Quality Loopbacks (targeted, not full restart)

| Failure Pattern | Loopback Target | Max Attempts |
|-----------------|-----------------|--------------|
| Missing footage / insufficient coverage | FOOTAGE_DISCOVERY | 3 |
| Weak/duplicate clips / invalid timestamps | CLIP_SCORING / TIMESTAMP_EXTRACTION | 3 |
| Black/frozen/broken frames / bad aspect | FOOTAGE_ACQUISITION / VISUAL_ANALYSIS | 3 |
| Audio clipping / silence / missing narration/music / bad ducking | AUDIO_PLAN | 3 |
| Missing story section / weak emotion / unreadable captions | EDIT_PLAN | 3 |
| Invalid edit_decisions / schema failure | EDIT_PLAN | 3 |
| Render failure | OPENMONTAGE_COMPOSE | 3 |
| Reused content risk | FOOTAGE_DISCOVERY | 3 |

**Limits:** 3 per category, 10 total; escalates to human after max

### 6. Discord Notifications

Events: run_started, sourcing_completed, editing_started, render_failed, quality_review_failed, loopback_triggered, run_completed, run_failed

### 7. Memory Update

After successful delivery:
- `hermes-football-memory-learning` skill produces `hermes_memory_update.json`
- Distills lessons to MEMORY.md (≤2,200 chars) / USER.md (≤1,375 chars)
- Full project record at `projects/<id>/football_emotion/project_record.json`
- Hindsight (if enabled): `local_embedded` mode, bank `hermes-{profile}`

## Known Limitations / Blockers

1. **YouTube DRM/geo restrictions:** Many high-quality World Cup clips are DRM-protected. Production runs need:
   - Pre-curated downloadable source lists (Archive.org, Creative Commons, user-supplied)
   - Or partnerships with licensed footage libraries
   - Fallback to user-provided YouTube links (supported in `football-source-discovery`)

2. **Hindsight memory:** Requires free persistent deployment (Oracle Cloud Free Tier / Fly.io) for `local_external` mode, or local LLM for `local_embedded`. Built-in memory + session search + project records work fully.

3. **Schema lock maintenance:** Must re-run `hermes-openmontage-repo-bridge` if OpenMontage schemas change.

4. **Live tournament sourcing:** Requires `shared/references/live-tournament-sourcing.md` workflow with rescan scheduling.
